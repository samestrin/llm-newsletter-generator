# Changelog

## Unreleased

- The daily archive workflow (`.github/workflows/daily.yml`) is removed: no workflow runs on a schedule. `tests/test_daily.py` keeps the offline `archive --demo` build test with its argv in the test. (epic 06)
- `newsletter issue --config FILE` and `newsletter serve --config FILE` read the file's feeds, web pages (`- page: URL`) and Hacker News (`- hackernews: {min_score, limit}`), group copies of one story into one story with all its sources, and rank the stories closest to the file's `topic` first, with one `embedding` call. `newsletter issue` now needs `NEWSLETTER_EMBEDDING_MODEL` (exit 2 without it). The run report (`RunReport.left_out`, `RunReport.grouping_error`, and both the Markdown and HTML reports) lists every item that could not be grouped or was dropped, and a failed embedding call; either one makes the run exit 1. A `serve` run that names no feeds reads the file's sources. `newsletter archive` no longer takes `--config`. (epic 02)
- `newsletter.sources.HackerNewsSource(min_score=..., limit=...)` reads the front-page stories from the public Hacker News API, one item each, and filters out stories scoring under the threshold. It uses the shared fetcher (timeout, size cap, private-address redirect check) and lists a failed story list or story in the run report (epic 02).
- `newsletter.sources.PageSource` reads single article pages: it fetches each URL with the RSS source's fetcher and robots.txt check, keeps the page's main text (its `article`, else `main`, else the element with the most paragraph text) and title, and lists a page robots.txt forbids, a failed load or a page with no text as a failure instead of fetching or skipping it. Every fetch, feeds included, now stops at 10 MB (`MAX_BYTES`) and refuses a redirect to a host that resolves to a private, loopback or link-local address, checked on every hop.
- `newsletter.grouping.group_items(items, llm, topic=...)` groups near-duplicate items into one story with all their sources and ranks the stories closest to the topic first (ties keep input order), from one `embedding` model call. A failed or unusable embedding call sets `error` and keeps every item as its own story; every ungrouped or dropped item is listed in `left_out` for the run report. Not yet wired into `newsletter issue` or `serve` (epic 02 T5).
- `--config FILE` on `newsletter issue` and `newsletter archive` reads a YAML sources file (`topic`, `sources`, `limits.per_feed`), validated on load: an invalid file exits 2 with an error naming the file and the field. Feed URLs, `--topic` and `--per-feed` on the command line win over the file. `pyyaml` is now a runtime dependency. (epic 02)
- `newsletter issue --html FILE` also writes the edited issue as the HTML email: every claim linked to its source, flagged claims marked, and the run report with the cost per step.
- `newsletter.export` sends an approved issue to Buttondown (`POST /v1/emails` with `status: draft`), Beehiiv (`POST /v2/publications/{id}/posts` with `status: draft`) and Resend (`POST /broadcasts` with `send: false`, and no send call) as a draft only. Each connector is optional, set up from its key in the environment, with a timeout (`NEWSLETTER_EXPORT_TIMEOUT`, default 30s). Export is refused before any request unless a person's approval sha256 matches the current text. A failed call or a reply that is not a draft is reported as failed and never as exported, a connector with no draft-only endpoint is dropped and listed, and no key appears in a log or the report.
- `docs/case-study.md` is a case study of the project's accuracy design — claims quoting sources, per-claim checks, a human approval gate — built around the eval table from `evals/results.md` (5/5 planted false claims flagged, 100.0% reference coverage, $0.0100 per issue), with the replay caveat kept.
- The README says what the tool does, step by step, with screenshots of the review page and of an issue as the HTML email, and shows the eval table from `evals/results.md`. That file is now committed: a replay of recorded responses, labeled as one, until a live run replaces it. The browser test saves the screenshots to `docs/img/` from the `open-models-week` eval case, and `tests/test_readme.py` fails if the README's table, `evals/results.md` or the screenshot fixtures fall out of date.
- `newsletter issue` now runs the editor pass: claims quoting their source, a faithfulness check and a reasoning-model edit, written as Markdown. Every claim links to its source, unsupported or unchecked claims are marked, and the run report lists failed feeds, dropped and flagged claims, the writer's voice and the cost per step. It needs `NEWSLETTER_REASONING_MODEL` as well as the fast model, and `--topic` now belongs to `newsletter archive` only. With `YOURVOICE_API_KEY` set, the voice pass rewrites only the editor's prose (intro, themes, why it matters); claims, quotes, numbers and citation links pass through unchanged, and a failed voice call keeps the neutral prose and is listed in the run report.
- `docker compose up --build` runs the API and the review page: a `Dockerfile` with an `api` and a `web` (nginx) target, and a `docker-compose.yml` that publishes only the page on `127.0.0.1:8080` and forwards `/api` to the API. `NEWSLETTER_API_TOKEN` is required. CI gains a `compose` job that starts both and checks the page, the proxied health call and the token.
- `web/` is a review page (React and Vite) for the API's drafts: read the text with its flagged claims and run report, edit and save it (which clears the approval), and approve it with the sha256 of the text read. Draft text is shown as text, never as HTML, and only http and https sources are links. CI gains a `web` job that builds the page and runs its unit tests and a Playwright browser test of edit and approve against a fake API.
- `newsletter archive --demo --site DIR FEED_URL...` drafts an issue and builds the static archive in demo mode: the approval is an `automated-demo` record, valid for archive pages only and refused by `newsletter.archive.require_export`; every page carries an "Automated demo" label and every summary is marked unchecked. `--per-feed N` (on `issue` too) summarizes only the first N items of each feed.
- `newsletter serve` runs an HTTP API (FastAPI and uvicorn) that runs an issue as a background job with a status and a timeout: the feeds, then the editor pass, then the voice pass, then render. Each run leaves a draft, a JSON file in `NEWSLETTER_DATA_DIR` holding the text, flags and run report, that can be listed, edited and approved. Approval stores the sha256 of the draft text and any edit clears it. A run past `NEWSLETTER_RUN_TIMEOUT`, or cut off by a restart, ends as a reported error with no draft. It binds `127.0.0.1` by default. Every call except the health check needs the `NEWSLETTER_API_TOKEN`, and every write also needs a JSON body and an allowed `Origin`. No secret appears in a response, error body, stored file or log.
- `newsletter issue` writes the summaries in the writer's voice when `YOURVOICE_API_KEY` is set. It builds a yourvoice.dev profile from `NEWSLETTER_VOICE_SAMPLES` and caches it, then rewrites each summary with the reasoning model. A rewrite that drops, changes or adds a link, quoted string, number or claim id is rejected. A rejected rewrite, a failure or a timeout keeps the neutral summary and is listed in the run report. `newsletter.render.build_report` takes the voice pass too, so the Markdown and HTML run reports list it as well.
- `python -m newsletter.evals` prints an eval table (faithfulness rate, flag rate, planted false claims flagged, reference coverage, cost per issue) from two committed past feeds, each with a reference issue and recorded model responses that include planted false claims; it exits 1 if a planted claim is not flagged and runs in CI. `--live` runs the same feeds against real models (costs credit); `-o evals/results.md` saves the table.
- The shipped prompt templates are now protected by snapshot tests, and the retired `introduction.md` and `closing.md` prompts are gone (`item.md` is now `summary.md` until epic 03 T6 replaces the legacy writer).
- `newsletter.archive.build_site(issues, site_dir)` renders approved issues to a static site: an index and one page per issue at `issues/YYYY-MM-DD/index.html`. All feed and model text is HTML-escaped, only http and https links are rendered, the run report shows problems by feed host and count only, and the site is built in a temp dir and swapped in only when complete.
- A `v*` tag builds the `api` and `web` images from `Dockerfile` and pushes them to `ghcr.io/samestrin/llm-newsletter-generator/api` and `.../web`, tagged with the version (`1.2.3` and `1.2`). A pull request that changes the `Dockerfile` or the release workflow builds both without pushing.
- Rewrote `README.md` for the new package: install with `uv`, the `newsletter` CLI, and the `NEWSLETTER_*` environment settings; dropped the version badge.
- `newsletter issue FEED_URL...` drafts a plain issue: one fast-model summary and one link per feed item, credits each feed, and ends with a run report of failed feeds, dropped entries and model calls with their tokens and cost. It exits 1 when anything failed.
- The prompt templates moved from `prompts/` to `src/newsletter/prompts/` so they ship with the package.
